# fund-manager-history

| 项 | 值 |
|---|---|
| `api_id` | `fund-manager-history` |
| 服务端登记名 | 基金历任基金经理 |
| 领域 | fund |
| 资料完整度 | 完整（请求 + 响应 + 口径均有） |

## 1. 功能与适用场景

从**基金视角**查询**历任基金经理**：每位经理的任期起止、任期天数、任期回报，并标识现任。

适用：用户问「这只基金换过哪些经理」「历任经理都是谁」「谁在管、管了多久」。

## 2. 不适用场景与易混接口

- 入参是**基金代码**；要查某个**人**的档案用 `fund-manager-info`（入参 `personalCode`）。
- 不需要姓名解析：本接口直接吃基金代码。

## 3. 请求参数

| 参数 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `fundCode` | string | 是 | 6 位基金代码 |

## 4. 调用示例

```bash
pixi run etf-htbr invoke fund-manager-history '{"fundCode":"510300"}'
```

## 5. 返回数据路径与关键字段

读 `$.data.managers[]`：

| 字段 | 含义 |
|---|---|
| 姓名 | 经理姓名 |
| 起止日期 | 任期起止 |
| 任期天数 | 在任天数 |
| `termReturnPct` | 任期回报（**小数**，`0.15` = 15%） |
| 学历 / 背景摘录 | 履历摘录 |
| `isCurrent` | `true` 为**现任** |

## 6. 数据口径

- `termReturnPct` 是**小数**不是百分数，展示时须 ×100 并加 `%`。
- 任期回报**仅客观陈述**，不评价经理优劣，不作横向排名。

## 7. 空数据与异常值语义

- HTTP 200 + 空数组 = 无历任经理记录（罕见），如实说明。
- 代码不可解析 → 404 `FUND_NOT_FOUND`。

## 8. 前置条件与调用限制

- 需已配置 API Key（`config.py status` 为 configured），网关可达；调用间隔建议 ≥ 3 秒。

## 9. 相关工作流

无（本接口自带基金代码，不进入姓名解析流程）。
