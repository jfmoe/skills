# fund-nav-trend

| 项 | 值 |
|---|---|
| `api_id` | `fund-nav-trend` |
| 服务端登记名 | 业绩走势 |
| 领域 | fund |
| 资料完整度 | 完整（请求 + 响应 + 口径均有） |
| 性质 | **业绩走势的主接口**（另有 2 个补充接口，见第 2 节） |

## 1. 功能与适用场景

查询指定**区间**内的净值走势与区间累计收益率，用于画走势图或回答「这段时间涨了多少」。

适用：用户问「这只基金这一年净值怎么走的」「帮我画个走势」「近三个月涨跌」。

## 2. 不适用场景与易混接口

- 只要**最新净值数字**用 `fund-nav`（逐日净值序列，可指定区间），不需要首日归零的走势线。
- **业绩走势是一个能力、三个接口**：本接口是主接口；`fund-benchmark-trend`（比较基准线）与 `index-performance-trend`（指数线）
  是同一张图的**补充数据源**，**默认不调**，仅当用户明确要求比基准/比指数时才追加。
- 三者叠加时的对齐口径见 `references/workflows/performance-trend-lines.md`。

## 3. 请求参数

| 参数 | 类型 | 必填 | 约束 |
|---|---|---|---|
| `fundCode` | string | 是 | 6 位基金代码 |
| `beginDate` | string | 是 | `yyyy-MM-dd` |
| `endDate` | string | 是 | `yyyy-MM-dd` |

> **三参必传**，缺任一将返回空序列（不报错）。

## 4. 调用示例

```bash
pixi run etf-htbr invoke fund-nav-trend '{"fundCode":"510300","beginDate":"yyyy-MM-dd","endDate":"yyyy-MM-dd"}'
```

## 5. 返回数据路径与关键字段

读 `$.data.trends[]`，**交易日升序（旧→新）**：

| 字段 | 含义 |
|---|---|
| `date` | 交易日 |
| `net` | 单位净值（**元**） |
| `value` | 区间累计收益率（**小数**，`0.1708` = +17.08%，复权净值链式累乘） |

## 6. 数据口径

- `value` 是**小数**，展示须 ×100 加 `%`；**首日恒为 0**（基准点）。
- **基准日 = `beginDate` 前的最后一个交易日**（无则取全史首日）。因此返回序列可能**回补** `beginDate` 之前的最后一个交易日，
  这是设计行为，不是数据越界。
- `value` 是复权口径的累计收益率，**不是净值**，不能当净值使用。

## 7. 空数据与异常值语义

- 三参齐全但区间内无交易日 → 空序列，如实说明该区间无数据。
- 缺任一参数 → 空序列（**不报错**），需先核对参数完整性再下「无数据」结论。

## 8. 前置条件与调用限制

- 需已配置 API Key（`config.py status` 为 configured），网关可达；调用间隔建议 ≥ 3 秒。
