# Workflow：基金名称与代码精确映射

## 适用与范围

用户只给基金名称，或现有基金代码与目标接口口径不同：先读 `references/apis/fund-resolve.md`。本流程只解析基金；经理姓名按 `manager-name-resolution.md`，公司和指数按各自接口处理。混合请求须拆分标的范围，不能把基金映射结果当指数代码。

## 编排

1. 先确定目标业务接口，阅读其单接口文档，明确需要 secuCode、gilCode 还是 innerCode。若参数名为 fundCode，也必须查清目标实际代码口径，不按名称猜。
2. 用户直接给出符合类型、格式及目标口径的代码时可直调；否则将原始名称或一种代码交给精确映射，不先补零或拼后缀。
3. 确认来源真实且未降级，再判断 matchCount：
   - 0：说明有效披露名称或代码未精确命中，请用户核对，结束本轮。不能据此断言基金不存在。
   - 1：直接取唯一候选中目标接口对应的代码字段续调，不再让用户确认。六位净码接口取 secuCode，GilCode 指标接口取 gilCode，明确要求内码时取 innerCode；仍按目标文档校验格式。
   - 大于 1：展示 matchedNames 和证券代码/GilCode 等可区分信息，编号后停下等用户选择，不按第一条、份额或知名度擅自挑选。
4. 用户确认后，只用选中完整代码组合续调；相同 innerCode 不代表不同 secuCode/gilCode 可以忽略。代码缺失或格式仍不满足目标时停下说明，不自行推导。

## 边界

名称只来自 MF_FundProdName 的有效 DisclName，不保证任意全称覆盖。无公网、模糊匹配、后缀猜测或额外缓存。matchedNames 仅表示本次命中行名称，不是完整别名库。真实失败按降级处理，不能假装零候选或拿演示映射续调。
