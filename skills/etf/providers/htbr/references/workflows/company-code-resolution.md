# Workflow：公司名称与编号精确映射

## 适用与范围

用户只给公司名称（如「华泰柏瑞基金」「华泰柏瑞基金管理有限公司」「HTBRJJ」），或需要确认某个名称对应哪家企业编号：先读 `references/apis/company-resolve.md`。本流程只解析公司；基金名称/代码按 `fund-code-resolution.md`，指数名称/代码按 `index-code-resolution.md`，经理姓名按 `manager-name-resolution.md`。混合请求须拆分标的范围，不能把公司解析结果当基金或指数代码。

## 目标接口 → 字段映射（续调前先对照）

| 目标接口 | 实际入参 | resolve 后取 |
|---|---|---|
| `fund-company-funds` | `companyCode` 公司内码列表 | `companyCode` |

公司维度目前只有 `fund-company-funds` 使用本解析结果；其余公司相关需求（规模、成立日等）走该接口的下游基金接口，不经公司编号。若参数名恰为 companyCode，也必须确认目标接口要的是公司编号而非基金代码。

## 编排

1. 先确定目标业务接口，阅读其单接口文档，确认入参要的是 `companyCode` 而不是基金代码或基金内码。
2. 用户直接给出公司编号（正整数）时可直接调用目标接口，不必无条件解析；只有名称时交给精确映射，不自行补「基金」「股份」等后缀。
3. 确认来源真实且未降级，再判断 matchCount：
   - 0：说明名称未精确命中，请用户换一种写法（全称/简称/拼音简称/英文名）核对，结束本轮。不能据此断言公司不存在。
   - 1：直接取唯一候选的 `companyCode` 续调，不再让用户确认。
   - 大于 1：展示各候选的 `companyName`（公司全称）、`parentCompany` 与 `matchedNames` 等可区分信息（同名主体与其分支机构常见），编号后停下等用户选择，不按第一条、编号大小或知名度擅自挑选。
4. 用户确认后，只用选中候选的 `companyCode` 续调；`parentCompany`、`listedCode` 为 `null` 是源表口径，不代表解析失败，也不要当 0 展示。

## 边界

名称只来自 `LC_InstiArchive` 四个名称字段的精确等值，不做模糊/拼音补全/大小写改写/括号归一。解析命中只代表名称在源表存在，不代表公司存续或有在管产品：下游 `fund-company-funds` 返回空数据时如实说明，不得据解析成功断言该公司有产品。无公网、后缀猜测或额外缓存。matchedNames 仅表示本次命中行名称，不是完整别名库。真实失败按降级处理，不能假装零候选或拿演示映射续调。
