# 维护提示词库

提示词库在 `~/Coder/skills/prompts/`，存放用户手动粘贴使用的提示词。一个提示词一个 Markdown 文件，文件内容就是提示词正文，文件名用 kebab-case 概括用途。

```text
prompts/
  lab/              试验区，扁平存放
  stable/<类型>/    稳定区，按提示词类型分一层目录
```

## 提示词的规范

库里的提示词会被粘贴到不同的项目和会话里反复使用，所以：

- **通用**：不带某个项目、业务或某次会话的内容，如文件路径、产品名、当时的窗口布置。必须因场合而变的地方，留给用户粘贴后自己补一句，不在正文里放占位符或选项。
- **起引导作用**：写背景、目标和取向，让模型自己决定怎么做。不写步骤，不替它定下具体的规则、阈值和文件布局。
- **简洁**：每句话都要能改变模型的做法；模型本来就会做的事不写。

从一次会话里提炼提示词时，会话中做出的具体决定属于那个项目，不写进去，只保留让这些决定成立的取向。

## 操作

- **记**：先在整个库里按主题搜索。已有同一用途的提示词就改它；没有才新建，默认放进 `lab/`，用户指明稳定区时放进 `stable/<类型>/`。
- **改**：在库里找到对应文件后修改。有多个候选时列出来让用户选。
- **转稳定**：用户说某个提示词稳定了，用 `git mv` 从 `lab/` 移到 `stable/<类型>/`。先看现有类型目录，都不合适时新建一个。
- **找**：按文件名和正文搜索，把提示词正文原样给用户。

正文保持用户给出的原文。用户要求润色或补充时才改写，并按上面的规范写。

## 先确认再写入

新建或修改提示词之前，先把改动以 diff 展示给用户，并写明文件路径；用户确认后才写文件，有意见就改稿再确认。提示词是用户自己要反复使用的文字，措辞由用户定。

转稳定和查找不改正文，不需要确认。

## 提交

写入后在 `~/Coder/skills` 里提交，只包含 `prompts/` 下的文件，直接提交到当前分支，不推送。这是用户对提示词库的长期授权，提交这一步无需再确认。
