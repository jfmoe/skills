# worktree 工人说明模板

`workers>1` 时，额外的工人各用一个 worktree：`git worktree add -b wt-<N> <路径> <主分支>`，路径放在仓库的同级目录；工人的 pane 用 `--cwd <路径>` 打开。把下面的内容复制到 `<本地目录>/worktree-brief.md`。

```markdown
# 并行实施补充说明（worktree）

你在独立的 worktree `<路径>` 中实施派给你的票，另一个工人同时在主工作树上实施其他票。除下面几条外，按 implement-brief 执行。

- 只在 `<路径>` 里改代码、跑检查，不修改、暂存或提交主工作树的文件。
- 每张票一个分支，命名为 `wt-<N>`，默认从最新的主分支新建；派发消息指定基点时，以派发消息为准。开始前先确认工作区干净。不 rebase、不 reset、不推送、不合并，合并由架构师 cherry-pick 完成。
- implement-brief 中的“提交到 <分支>”，这里改为“提交到本票分支”。
- `<本地目录>/issue-<N>/` 写在主仓库（`<主仓库>/<本地目录>/issue-<N>/`）；构建产物和检查缓存留在 worktree 内。
- 第一次构建是冷构建；依赖缺失时，按锁文件安装。
- CHANGELOG 这类共享文件，只追加本票的条目，不重排已有内容。
- 最后一条回复除提交号外，写明分支名。
```
