# 过程评审说明模板

发给一个空闲的 Agent，填上票号、实施者 pane、会话文件、工作树、派发时间和提交号。会话文件由调度记录里该票的 `agent_session` 定位（Codex 在 `~/.codex/sessions/`，Claude 在 `~/.claude/projects/`，按文件名匹配）。

```markdown
按下面的要求评审 #<N> 的实施过程（实施者 <pane>，会话文件 <路径>，工作树 <路径>，<时间> 派发，提交 <sha>），写入 <主仓库>/<本地目录>/process-review-<N>.md。

只读：不改仓库文件，不跑检查和付费运行。证据取自上面的会话文件、<本地目录>/issue-<N>/、Issue 评论和 git。命令次数按实际执行的事件统计，不按命令文本匹配统计（日志和提交说明里出现的命令名会被误算）。

回答：
1. 时间线：派发到提交，按读码设计、写码、目标测试、质量工具、各道门槛、排查、等待裁定、收尾切分，附起止时间。
2. 门槛：每道门槛的次数和耗时；同一份源码上的重复运行、源码定稿前跑的重门槛、无关的测试、强制重跑，逐条列出时间和命令。
3. 对照：与 <基线文件> 比较派发到提交的时长、固定开销占比和改动规模。
4. 剩余浪费：按耗时从大到小排列，写明根因（规则不清、规则冲突、工具问题、测试设计、模型倾向），并给出一句精简的拟改文档句子，或一处工具改动。
5. 规则效果：项目的每条流程规则是被遵守、被忽略还是被误解。

文件开头用三到五行写结论；最后一条回复只写文件路径和这几行结论。
```
