# 用 WDA 操作 iOS 真机

下文的 `wda` 指 `python3 -I <本技能目录>/scripts/wda.py`。它是一个只依赖 Python 标准库的命令行工具，录屏另外需要 ffmpeg。完整用法看 `wda --help`。

- 坐标一律用 point。
- 状态目录是 `~/.local/share/ios-wda`（配置、WDA 源码、构建产物、`logs/`），可以用环境变量 `WDA_HOME` 改。

## 开始前

1. 运行 `wda status`。输出以 `ready` 开头就能直接用。这一行同时给出设备、前台 App、屏幕尺寸（point）和锁屏状态。
2. 输出是 `not ready`，运行 `wda start`。它会启动 USB 转发和 WDA runner（设备上已经有 WDA 在跑时直接复用），就绪后再打印一次状态。
3. 报 `not configured` 或 `no build`，或者是新的 Mac、新的设备，按[首次配置](references/setup.md)操作。
4. 其他报错，先运行 `wda doctor`，再查[故障表](references/setup.md#故障表)。

**完成标准**：`wda status` 输出 `ready`，锁屏状态是 `unlocked`，前台是要操作的 App。
- 显示 `LOCKED`，按下面"需要用户接手"的流程处理。
- 前台不是目标 App，运行 `wda activate <bundle id>`。不知道 bundle ID，用 `wda apps 关键词` 查。这里的名称是 App 包里的名字，可能是英文，和主屏幕上显示的不一定一样。

## 操作循环

每一步都是"看 → 做 → 确认"。WDA 返回成功，只说明手势已经发给了设备，不代表 App 按预期做出了反应。

### 看

优先读文字，比截图省 token。

| 命令 | 作用 |
|---|---|
| `wda tree -i` | 只列可交互的元素 |
| `wda tree` | 列出所有带文字的元素 |
| `wda find 文字` | 按文字查找，屏幕外的元素也会列出来 |

输出每行一个元素，格式是 `类型 '文字' ='值' @中心x,中心y 宽x高`；不可用的元素，行末标 `disabled`。

匹配规则：`find`、`wait`、`tap --text` 以及选项 `--find`、`--wait` 用的是同一套规则。
- 先找文字完全相同的元素；没有，再找文字或值里包含它的。
- 同一档里，可用、可交互的元素排在前面；其余按控件树里的顺序排。
- 除了 `find`，其他命令都只看屏幕内的元素。这里只按屏幕边界判断：菜单、列表等滚动区域里被裁掉的元素仍可能列出来，点了没反应就截图确认，先把它滚进可见区域。

文字信息不够时再截图：
- `wda shot [路径]`，默认路径是 `/tmp/wda-shot.jpg`。截完用 Read 查看。
- 图片尺寸默认等于屏幕的 point 尺寸，所以图上的像素坐标就是点击坐标。
- 省 token 的用法：`--scale 0.5` 看整体布局；`--crop X,Y,W,H --scale 2` 只放大局部，看清小字。缩放或裁剪后，换算回 point 的公式是"裁剪原点 + 像素 / 倍数"。

### 做

| 命令 | 作用 |
|---|---|
| `tap X Y`、`tap --text 确定` | 点击。按文字点击时点匹配结果的第一个，输出里会写出实际点中了哪个元素 |
| `doubletap X Y`、`hold X Y [秒]` | 双击、长按 |
| `swipe X1 Y1 X2 Y2 [--ms 300] [--hold-ms 0]` | 滑动。翻页、快速滑动用较短的 `--ms`；要先按住再拖，用 `--hold-ms` |
| `pinch CX CY 起始间距 结束间距 [--ms 400]` | 两根手指以 (CX,CY) 为中心水平移动。间距指两指之间的距离（point），结束间距大于起始间距是放大 |
| `type 文本` | 输入到当前有焦点的输入框，密码框也可以。先点中输入框再输入。文本以 `-` 开头时写成 `type -- -abc` |
| `home`、`activate <bundle id>`、`terminate <bundle id>`、`orient portrait\|landscape` | 回主屏幕；把 App 切到前台，没在运行就启动它；结束 App；转屏 |
| `alert`、`alert --tap 按钮` | 查看系统弹窗的文字和按钮，没有弹窗时报 404；点弹窗里的某个按钮。按钮文字以 `alert` 的输出为准，会随系统语言变化 |

### 确认

动作命令执行后输出 `ok <动作> t=<发出动作时的 epoch>`。在同一次调用里可以接着观察：
- `--wait 文字`：最多等 10 秒，直到这段文字出现。适合确认页面已经跳转，文字要选目标页独有的；上一页也有的文字，起不到确认作用。
- `--find 文字`：只打印匹配的元素。
- `--tree`：打印所有可见元素。
- `--shot [路径] [--scale S]`：截图。

除了 `--wait`，其他几项都会先等 `--settle` 秒（默认 0.6）再观察。单独等待用 `wda wait 文字 [--timeout 10]`，不要用固定的 sleep。

### 批量

步骤已经确定、中间不需要看结果时，用 `do` 一次执行多步：

```
wda do 'tap --text 搜索' 'type 条漫' 'tap --text 确定' --wait 结果
```

- 每个步骤是一条带引号的子命令。可以用的有：上面所有动作命令，以及 `wait`、`find`、`tree`、`shot`、`sleep 秒`、`app`、`alert`。单个步骤也能带自己的 `--wait`、`--find`。
- 末尾的观察选项在全部步骤执行完之后才运行。
- 后一步要点的元素是前一步才出现的（键盘按钮、弹窗、新页面），给前一步加 `--wait 该元素的文字`。
- 执行到第一个失败的步骤就停下，报错里写明失败的是第几步、前面完成了几步。没执行的步骤不会补跑。

### 其他命令

- `app`：查看前台 App。
- `settings JSON`：修改会话设置。
- `get` / `post` / `delete 路径`：直接调用 WDA 的任意接口。
  - `--root` 表示路径从服务根开始，不加则相对于当前会话。
  - `--out 文件` 把完整结果写进文件；不加时只打印前 4000 字。
  - 常用接口见[接口速查](references/api.md)。

## 断线与恢复

- **自动恢复**：命令发现服务连不上时，会自动补起转发和 runner，大约 10 秒，然后：
  - 读操作，以及确定还没发到设备的动作：自动重试。
  - 可能已经发到设备的动作：不会自动重发，只报"可能已执行"。这时先 `tree` 或 `shot` 看实际状态，再决定要不要重做，避免重复点击或重复提交。
- **报错附带现场**：动作报错时，报错行末尾会附上设备状态：`device LOCKED`（设备锁屏），或者 `foreground <bundle id>`（当前前台 App，可以看出是不是被带到了别的 App）。
- **恢复不了**：设备锁屏、休眠或拔线时，自动恢复会失败。按下面的流程请用户处理。

## 需要用户接手

解锁设备、点"信任"、登录账户、输入验证码、通过 Face ID 等必须由用户本人完成的事：
1. 停止所有设备操作，告诉用户要在哪个页面做什么、做完之后你会接着做什么。
2. 有提问工具就用它提问，第一个选项固定为"已完成继续"。没有提问工具，就用文字说明，然后等用户回复。
3. 收到用户明确的完成答复后，先运行 `wda status`，再用 `tree` 或 `shot` 重新观察。之前的坐标和页面判断全部作废。

用户想实时看设备画面时，让用户在浏览器里打开 `http://127.0.0.1:9100`（MJPEG 画面流）。

## 注意

- **自绘内容**：图片、漫画页、游戏画面、App 自己画的弹窗，控件树里可能没有。这类内容以截图为准，按坐标操作。
- **系统界面坐标**：主屏幕、控制中心、系统分享浮窗这类系统界面，控件树给出的坐标可能对不上屏幕：横屏时给的是竖屏坐标，或者是相对浮窗原点的坐标。按文字点偏了，就改按截图坐标点。
- **凭据**：`type` 只输入用户明确给出、用于测试的凭据。
- **核对密码框**：截图里不显示圆点。用 `wda find` 找到 SecureTextField 那一行，`='•••'` 里的圆点数应该等于输入的位数。
- **一台设备同时只有一个 agent 操作**：`wda` 有操作锁，并发的命令会排队执行，不会交叉。但多个 agent 轮流操作时，界面状态会互相干扰。

## 录屏

`wda record 秒数 输出.mp4 [--pct 25]` 走 MJPEG 流，录屏时可以继续操作。
- 帧率由设备截屏的速度决定，iPad Pro 上约 20fps，即每帧约 50ms 的精度。
- `--pct` 是画面尺寸占屏幕像素尺寸的百分比，不是占 point 尺寸的百分比。2 倍屏上 `--pct 50` 得到的画面正好等于 point 尺寸，比如 iPad Pro 是 1366×1024。录完会恢复原来的流设置。
- 用法：在后台启动录屏，等 2～3 秒再做动作。动作在视频里的时刻 = 动作输出的 `t` − 录屏输出的 `movie_t0_epoch`。
- 找画面发生变化的时间点：`ffmpeg -i 输出.mp4 -vf "select='gt(scene,0.002)',showinfo" -f null - 2>&1 | grep -o 'pts_time:[0-9.]*'`。第一次和最后一次变化之间的时长就是动画时长，其中包含手指移动的时间。
