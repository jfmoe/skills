# 任务书

任务书原文保存在 `research/_process/briefs/`，执行方读文件执行，主导方的派单指令只写一句"读取某某文件并按要求执行"，再交代当前设备和轮次。下面是模板，`<>` 处按实际情况替换。

## R1 广度遍历

```text
任务：<App> 竞品调研第 1 轮"广度遍历"。用 ios-wda 技能操作已连接的 <设备>（App 已安装，bundle ID <id>）。
先读 research/README.md 的记录规范，严格按它写。这一轮只摸清"界面上有什么"，不深测行为。

1. 记录环境：系统版本、App 版本，填进 research/<app>/README.md。
2. 走遍所有可达页面：每个 tab、按钮、长按菜单、更多菜单、弹窗、核心功能里的各级面板、付费页。写入 screens.md：每个页面一条 SC 事实，写明进入路径、全部控件和文字原文、能跳到哪些页面；文件开头放页面层级树。
3. 所有设置项写入 settings.md：所在页面、名称原文、选项全集、默认值（以当前值为准，注明"当前值"）、是否带付费锁。效果留到第 2 轮。
4. 付费页只记录看到的内容：权益、价格、档位、试用说明原文。
5. 每条事实配截图，当场复制到 screenshots/<设备>/<前缀>/，文件名以编号开头。证据不写进表格，表格只有编号、设备、主题、事实、路径五列。

约束：不付款，不点"恢复购买"，不登录账号，不改系统设置。切换过的设置项在本轮结束前改回原值。没把握的写进 untested.md。
工具观察：核心内容在控件树里是否可见，哪些操作只能按截图坐标做，边缘滑动等系统手势是否生效。结果写进 _process/notes.md。
完成后用几行回复：写了哪些文件、各有多少条事实、没走到的入口及原因。不贴文件内容。
```

## 第二台设备对照

```text
任务：第 1 轮 <设备 B> 对照遍历。不重新完整遍历，以 screens.md、settings.md 为基准：
- 在 screens.md 末尾加"<设备 B> 对照"表，每个 SC 编号都要给出一致、有差异或未找到的结论；进不去的写"未进入"和原因。
- 设备 B 独有的页面、控件、设置，作为新的 SC / ST 条目追加。
- 横屏、竖屏各看一遍。App 内没有方向入口时，用 `wda orient` 转屏。
- 截图文件名加 -<设备> 后缀。
- 主导方已把 ios-wda 切换到设备 B。开始前先 `wda status`，确认型号是设备 B 且处于解锁状态；不对就停下来报告。
```

## R2 通用要求

每个模块的任务书都要求执行方先读这一份。落地为 `_process/briefs/r2-common.md`：

```text
## 输入
- 记录规范 research/README.md；R1 产物 screens.md、settings.md（用来定位入口）。
- 测试素材的位置和清单；素材上的标记怎么读。

## 设备
- 先确认当前连接的设备，如实填写"设备"列。
- 另一端已有同一检查项的结果时，这一端只做复核。
- 用 ios-wda 技能操作设备。每次手势之后都观察确认结果；漫画页等自绘内容以截图为准。
- 截图用 `wda shot` 直接存到调研目录里的最终路径，按规范命名。
- 密码框只输入任务书给出的测试服务密码，输入后用 `wda find` 核对圆点数。

## 怎么测
- 每个检查项都要实际操作，写下操作和结果。界面原文照录。
- 依据素材上的标记来判断：色带说明哪条边在屏幕内，页码和 L/R 说明页序和拆页，网格格数说明缩放倍数。
- 设置项的效果逐个选项切换并观察，写回 settings.md 的"效果"列。
- 同一个行为在不同模式下要分别测，事实里写明所处的模式。
- 动效测量按 _process/briefs/r2-common.md 末尾的规程（从本技能的 references/motion.md 落地）。
- 时长写明口径：是否包含手指的移动，用了哪种录屏方式，精度多少。

## 约束
- 不付款，不点"恢复购买""订阅"，不登录第三方账号，不改系统设置。
- 系统权限：<本地网络已授权>；其他权限记录弹窗原文后选不授予，继续测。
- App 内部的密码或 PIN（比如隐私密码）：不要自己设置，记录界面原文，写进 untested.md，原因写"待用户确认"。
- 遇到付费锁，只记录锁的位置、文案、触发的付费页，不想办法绕过。
- 改过的设置，模块测完后恢复；恢复不了的写明现状。
- 需要服务器的时候，先停下来报告，由主导方搭好环境。

## 收尾
- 运行 `python3 -I research/tools/build_indexes.py research/<app>` 更新索引。
- 工具和流程方面的观察，追加到 _process/notes.md 的"R2-<前缀> 工具观察"。
- 用几行回复：写了哪些文件、新增多少条事实、没完成的检查项及原因。
```

## R2 模块检查项

每个模块的任务书：开头一句"先读 r2-common.md"，然后写本模块的事实文件、前缀，最后是编号的检查项清单。审核时发现的遗漏，写在下一段任务书开头的"0. 补测"小节里。

**导入（IM）**
- 列出全部导入入口和选项原文。
- 每个素材文件逐一导入，记录：导入过程中的界面、成功或失败、书库里显示的名称、封面、页数，以及首尾页的标记（用来核对顺序）。
- 文件夹导入后的组织方式；结构识别（多级目录、分卷、元数据文件）。
- 加密文件：先输错误密码，再输正确密码。
- 编码问题；多选导入；重复导入。
- 其他入口：分享扩展、Wi-Fi 传输（Mac 端用 curl 上传）、HTTP 下载。需要账号的入口，只记录表单字段原文。
- 导入前后存储占用的变化。

**书库（LB）**
- 布局和显示模式；每种排序在升序、降序下前 N 项的顺序（用批量素材）；筛选条件。
- 单项长按菜单的每一项都执行一遍；批量操作。
- 合集或文件夹：新建、改名、加入、移出、删除、自动归并。
- 搜索：多种文字分别搜。最近记录、书签。封面的提取规则和更换方式。
- 删除后文件是否真的被物理删除（通过 Wi-Fi 传输的文件列表或下载核对）。
- 书库设置里各开关的效果。

**付费（PW）**
- 试用的显示；所有付费页入口（含启动时自动弹出），各入口的内容是否相同。
- 档位、价格、货币、标签、倒计时原文；倒计时重启后会不会重置；切换档位时权益文案有没有变化。
- 遍历所有入口，记录锁标记。试用期内没看到标记的写"未见标记"，不写"免费"。
- 功能内部的额度提示；账号体系；"恢复购买"和订阅管理只记录位置。

**服务器和网络源（SV）**
- 对每种服务：添加（含故意填错地址、错误密码）、浏览、排序、搜索。
- 流式打开的过程（动效测量）、下载、进度是否进入书库和最近记录、编辑、删除。
- 服务端能看到的状态，比如 Komga 网页端的阅读进度。
- 有评论提到的问题，逐条验证。

**其他（MS）**
- 统计口径；外观三种模式；切换语言后的文案；更换应用图标；隐私类设置；缓存的分类和清理前后的影响。
- 实验室、社区、反馈页面的原文（不提交）。
- 系统集成：打开方式、分享扩展、小组件、快捷指令、拖放。
- iPad 专属的分屏、键盘：做不到的写进 untested.md。

**核心模块**按品类写专门的清单，按小节拆成 2～3 次任务：阅读类见[阅读器检查项](core-reader.md)。其他品类参照它的结构：
- 打开与续读；
- 模式 × 方向 × 手势的组合；
- 适配和边界情况（用标记素材）；
- 极端内容（超大、超长、损坏的文件）；
- 导航与进度；
- 附加功能（AI、翻译等）。
每节都要配上动效测量。
