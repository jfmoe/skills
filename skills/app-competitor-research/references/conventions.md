# 记录规范

新建调研时，把本文件落地为 `research/README.md`，执行方按它写事实。

## 客观性

- 只写能观察到的行为，界面上的文字原文照录，包括错别字和标点。
- 不用评价词，比如"流畅""卡顿""好用""简洁"。手感类特性拆成可观察的行为来记：放大倍数、有没有动画、动画是什么形态、多长时间、会不会回弹、点击区域怎么划分、手势触发后的结果。
- 观察不到的项不推测，写进 `untested.md`，写明原因和需要的配合。
- 证据只能证明一部分时，写清边界，比如"不能据此判定……""只验证了本次样本"。
- 第三方说法（评论、社区帖子）原文引用，注明来源和日期，不收录昵称，只作为"某人说了什么"的事实。
- 界面上的说明文案只算文案，不等于行为已经验证。

## 事实条目

事实文件是给后续做分析的 agent 读的，格式以读取成本低为准：每条事实独占一行，按编号 grep 一行就能读到；同一文件内固定不变的信息写在开头，不在每行重复。

文件开头写一段"本文件口径"：来源（通常是真机）、App 版本、设备、测量方式和精度。个别行例外时，在该行的事实里注明。

表格五列：

| 列 | 内容 |
|---|---|
| 编号 | `<前缀>-<三位序号>`。编号分配后不再变动；删除的条目保留编号，标注"已撤回" |
| 设备 | `iPhone`、`iPad`；两端都验证过且一致时写 `通用` |
| 主题 | 不超过 12 个字的中性主题词，如"双击行为""跨页配对"，用来生成索引 |
| 事实 | 观察到的行为、界面原文、测量值。只在口径和文件开头不同时说明 |
| 路径 | 从 App 首页出发的操作路径，如 `书架 → 长按封面 → 菜单` |

- 证据不写进表格。证据文件名以编号开头，`ls screenshots/*/<前缀>/<编号>*` 就能找到；录像文件名也以编号开头。
- 结构相同的多条结果（比如每个素材的导入结果、模式 × 方向的组合）合并成一张矩阵表，挂在一条事实下面，矩阵里不再重复写口径。
- `build_indexes.py <app 目录>` 会生成 `INDEX.md`（每条事实一行：编号、设备、主题、所在文件）和 `screenshots/index.md`（给人看的可点击证据）。新增或修改事实后都重新运行一次。读事实时先看 INDEX.md，再按编号 grep。

## 设备维度

- 截图按 `screenshots/<iphone|ipad>/<前缀>/` 分目录存放；iPad 截图文件名在编号后加 `-ipad`。
- 第二台设备上做对照时，在 `screens.md` 末尾加一节"<设备> 对照"，列为：SC 编号、一致 / 有差异 / 未找到、差异原文；截图按命名规则存放，不进表格。布局不同就算"有差异"。
- 一端已经测过的行为，另一端只做复核：一致就把设备列改成 `通用` 并补上截图；不一致就新增一条事实。

## 证据

- 文件名用 `<编号>-<英文短描述>.jpg`，一条事实有多张图时加 `-a`、`-b`；iPad 截图在编号后加 `-ipad`；动效关键帧用 `<编号>-<描述>-seg<N>-start|mid|end.jpg`。
- 截图用 `wda shot <路径>` 直接存进调研目录。默认尺寸等于屏幕的 point 尺寸；要看清小字，另存一张 `--crop` 放大的局部图。
- 文件名要和图片内容一致。
- 截图、录像、测试素材都用 Git LFS 提交：`git lfs track 'research/*/screenshots/**/*.jpg' 'research/*/screenshots/**/*.png' 'research/*/recordings/**' 'research/test-materials/out/**'`。录像是动效事实唯一的原始证据；素材入库的是实际使用的那一版，重新生成不保证字节一致。
- 录像放在 `recordings/<前缀>/`，文件名以编号开头。测量的明细（每段的时间戳等）放在 `screenshots/<设备>/<前缀>/<前缀>-measurements.md`，事实里只写结论值。

## 环境

`<app>/README.md` 记录：调研日期、设备型号和系统版本、App 版本及期间的变化、权限的授予情况、会员或试用状态、测试内容来源。
