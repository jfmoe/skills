背景：这个项目经过长期迭代，经手过不同的 agent，agent 能读到的提示词和文档已经混乱。

需求：梳理整个项目中 agent 能看到的全部内容（AGENTS.md / CLAUDE.md、项目内的 skill、docs、ADR、README、术语表），目标是让 agent 在这里的开发体验最好。

要做的事：

1. **删除**：过时内容、废话、调研记录、设计草稿、验收记录这类一次性产物直接删，不建归档目录，需要时从 git 历史里找。之后的一次性产物放进不入库的本地目录。
2. **去重**：每条事实只留一个归属处，其余地方删掉或指向它。默认的归属：
   - 实现细节（常量、算法、消息文本、模块做什么）归代码，文档不复述；
   - 用户可见的行为归产品文档或产品 skill；
   - 为什么这样做、试过又放弃了什么，归 ADR；
   - 跨模块、不随日常改动变化的整体结构，归一份短的架构文档；
   - 术语的含义归术语表；
   - 操作流程归流程文档；
   - 无处安放的约束，写成以规则命名的测试或用类型表达，不靠注释和文档。

   复述代码的文档类别整个删掉，不要改写它。动手前先盘点每份文档里只此一处的内容占多少，再决定这个类别留不留。
3. **放宽**：提示词按顶级模型来写，写事实和原因，不写步骤清单式的硬性规定。绝对措辞（never、always）只留给能在提交历史里查到事故的规则；查不到依据的规则删掉。
4. **ADR**：按决定主题重新整理，只保留仍然有效的决定；被取代的直接删除，编号不复用。
5. **维护规则**：把以上原则写进 AGENTS.md，让以后的 agent 照着维护，避免再次混乱。能低成本机械判定、并且对应一种真实发生过的混乱的规则，做成检查，失败信息里写明怎么改；需要判断的规则只写进提示词，交给评审，不要为文档的格式和措辞写测试。

约束：

- 文档描述的每条事实，写下之前对照代码核实，不照抄旧文。旧文档与代码不符时以代码为准，并告诉我。
- 删除一段内容之前，确认其中仍然成立、别处没有的规则已经移到归属处，并列出移了什么。
- 不改变产品行为。不往生产代码里补注释来承载从文档里删掉的内容。
- 这个仓库之外的文件（全局指引、个人 skill 仓库）不改，只提建议。
- 文档语言：<公开项目用英文 / 私有项目用中文>。
