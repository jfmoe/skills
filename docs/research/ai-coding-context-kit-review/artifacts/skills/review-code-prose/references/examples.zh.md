# 提炼后的文字示例

这些示例用于识别支配原则，不是可直接套用的文本模板。“平衡版本”会保留每项关键命题，同时只使用该位置所需的最少解释。

## 保留每个事实条款

**原文：** “The coordinator carefully serializes writes per session, flushes buffered events before disposal resolves, and reports backend failures to the caller.”

**过度精简：** “协调器串行处理持久化。”

**平衡版本：** “协调器按会话串行写入，在 dispose 完成前刷新缓冲事件，并向调用方报告后端失败。”

删除修饰和重复，不要删除命题。主体、按会话范围、dispose 顺序和失败可见性是相互独立的事实。

## Skill 的明确范围具有实际作用

**过度精简：** “阅读来源并运用判断。”

**平衡版本：** “本 Skill 是指导，不是完整检查清单。除具名检查外仍需运用判断；已有文档要求继续适用。”

**过度详细：** 用数段文字论证列表为何不能替代独立推理。

保留明确限制，因为它会改变 agent 应用工作流的方式。精简重复论证，不要删除护栏。

## 实操流程保留动作和验证

**过度精简：** “为工具添加测试。”

**平衡版本：** “在单元层测试注册和 dispose，通过真实 loader 路径执行工具；渲染输出变化时增加快照。确认断言观察外部结果，而不是模型自述。”

**过度详细：** 逐一叙述示例代码中已经可见的每个 fixture 文件和断言。

保留测试层级、必要动作、真实入口和可观察验证。删除 fixture 叙述。

## 保留所有权和时机

**过度精简：** “销毁期间取消提供方任务。”

**平衡版本：** “运行时先请求提供方取消，再释放子作用域；提供方仍负责在 dispose 完成前等待其 worker 退出。”

**过度详细：** 按时间顺序叙述实现销毁的每个 promise 和回调。

主体、顺序、所有权转移点和完成保证是不同事实条款。

## 事件 JSDoc 保留边界时机

**过度精简：** “组合并缓存会话前缀。”

**平衡版本：** “在第一次 pre-step 和模型请求前只组合一次会话前缀。监听器追加内容进入当前请求，pre-step 压力统计接收已组合前缀。”

**过度详细：** 逐步叙述实现该顺序的循环辅助函数、缓存字段和 promise 回调。

事件顺序及其对当前请求的影响属于调用方可见行为，不是实现叙述。

## 为复杂代码提供方向，不叙述代码

**过度精简：** “支持 worker realm。”

**平衡版本：** “拥有 worker realm 及其宿主桥接。realm 初始化只执行一次；dispose 会终止 worker，并拒绝后续调用。协议理由见 worker 隔离决策记录。”

**过度详细：** 按段预告下方每个类和辅助函数。

保留模块角色、依赖、职责和不明显的生命周期行为。架构理由使用链接，局部控制流交给代码表达。

## 公共 JSDoc 包含失败行为

**过度精简：** “返回 realm 全局对象。”

**平衡版本：** “返回已初始化的 realm 全局对象。初始化尚未完成或 realm 已 dispose 时抛错。”

**过度详细：** 说明导致每次抛错的内部状态机分支和具体辅助调用。

抛错和状态前置条件属于调用方可见的约定事实。

## 保留精简的实现映射

**过度精简：** “由外部 API 支持的搜索提供方。”

**平衡版本：** “将每个提供方结果映射到共享搜索结果字段，保留标题、URL 和文本，省略提供方专有的排名元数据。”

**过度详细：** 逐字段复述映射代码，包括名称相同且赋值明显的字段。

保留能够解释适配器在哪里丢弃或改变信息的映射细节。

## 链接理由，同时保留局部约定

**过度精简：** “dispose 已记录在生命周期决策记录中。”

**平衡版本：** “dispose 会中断运行并等待提供方完全停稳。所有权和竞态处理见生命周期决策记录。”

**过度详细：** 在每个 disposer 旁重复决策记录中的 promise 调度和被否决的所有权模型。

在调用方需要的位置保留行为和完成保证。算法和理由应积极链接；链接不能替代局部约定。

## 已实施决策记录保留验证约定

**过度精简：** 因决策已经发布而删除整个 Testing 章节。

**平衡版本：** “单元测试覆盖发布前后取消、dispose 完全停稳和提供方重载。构建入口冒烟测试覆盖真实 loader 路径；由于传输依赖具体进程，快照覆盖暂缓。”

**过度详细：** 按文件叙述 fixture 和断言，却没有补充行为区别。

删除迁移任务和测试过程叙述。保留测试层级、固定的行为、真实入口和具名覆盖缺口。

## 安全边界可能需要一个具体示例

**过度精简：** “挂载的插件共享宿主权限。”

**平衡版本：** “挂载的插件共享宿主权限；例如，访问 `ctx.shell` 后可以用宿主执行器的权限运行命令。”

**过度详细：** 罗列插件可能滥用的所有服务和每种假想攻击。

当一个抽象安全限制需要示例才能变得可操作时，保留一个示例即可。

## 完整删除推理过程

**过度详细：** “循环先检查值是否缺失。如果缺失，下一个分支提前返回。否则继续执行，因此最终断言是安全的。”

**平衡版本：** 当代码已表达这些分支时，不写注释。如果提前返回保护了不明显的不变量，只说明该不变量。

不要把推理过程压缩成更短的叙述；应直接删除。

## 配置注释解释配置树无法表达的内容

**过度详细：** “本配置项加载本地文件系统提供方，然后加载策略插件，再加载读取、写入和编辑工具。”相邻配置项已经清楚显示该顺序。

**平衡版本：** “在面向模型的工具之前加载策略，使其写入和编辑调用经过‘修改前先读取’门禁。”

保留顺序的后果、意外的作用域规则或安全边界。配置清单本身交给配置表达。

## 不要只为减少字数而精简

**当前版本：** “适配器把提供方错误转换为共享错误类型，使调用方可以统一处理认证、限流和瞬时失败。”

**更短但更差：** “适配器规范化提供方错误。”

**平衡判断：** 除非链接或周边约定已经列出这些失败类别，否则保留当前句子。短版本丢失了后果和区别，没有改善结构。

## 模型可见文本遵循所有权

**过度精简：** “调用失败时，工具返回错误。”

**过度详细：** 把另一个包的 schema 和渲染字符串复制到当前后端 README。

**平衡版本：** 引用当前包拥有的稳定提示词、结果和错误文本。schema 链接到生成的工具目录；其他包拥有的文本链接到消费方 README；局部只说明当前包自己的条件或差异。

进入模型的文字属于行为，但重复内容仍会漂移。精确文本应保存在所有者处。

## 生成摘要必须能够独立成立

**过度精简：** “审批请求和策略服务。”所有者在后文解释了策略顺序和审计日志，但目录只导出第一句。

**过度详细：** 把服务完整生命周期和提示通知行为都移入被提取的句子。

**平衡版本：** “审批服务在 answerer 之前应用会话策略，并把每组请求／结果记录到请求会话。”目录之外的细节保留在后续句子。

必须了解生成器提取什么。被导出的片段需要保留生成输出上所需的约定。

## 限制属于约定，不是技术债清单

**过度精简：** 省略进程生命周期缓存，导致配置变化需要重载插件这一事实消失。

**过度详细：** 罗列对调用方或维护者没有影响的私有辅助函数清理和未使用测试访问器。

**平衡版本：** “提供方选择在插件生命周期内缓存；安装或修复提供方后需要重载。”

保留影响使用或安全维护的缺口和不明显约束。包 README 不是待办事项清单。
