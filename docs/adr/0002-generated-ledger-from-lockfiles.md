# Cross-project skill inventory is generated from lockfiles, not hand-maintained

The ledger (`registry/third-party.md` and `registry/inventory.json`) is regenerated by `sync-registry.mjs`, which scans the global lock (`~/.agents/.skill-lock.json`), each scanned project's `skills-lock.json`, and the fork `meta.yaml` files under `registry/upstream/`. The only hand-maintained input is `registry/projects.yaml` (the list of project paths to scan). We chose generation because the previous hand-maintained ledger drifted badly — it recorded 4 global third-party skills when 9 were actually installed (verified during the redesign).

## Consequences

- Per-project reproducibility is owned by each project's own `skills-lock.json`, which `npx skills` maintains natively. The central ledger is only a cross-project overview, not a source of truth for installs.
- Output is sorted and timestamp-free so repeated runs are stable and diff cleanly in git.
- Self-created skills (`source: jfmoe/skills`, or `sourceType: local` resolving to this repo root) are excluded from the third-party sections.
- A missing project path or absent `skills-lock.json` is skipped and noted, not fatal.
