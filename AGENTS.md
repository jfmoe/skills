# AGENTS.md

This repository is the personal source repository for user-created agent skills.

## Structure

- Self-created skills live under `skills/<skill>/SKILL.md` — one flat level, no category directories (see ADR-0004).
- Three classes of skills:
  - **Original**: purely self-created. Lives in `skills/<skill>/`.
  - **Fork**: a modified copy of a third-party skill. The installable copy lives in `skills/<skill>/`; a pristine upstream snapshot lives in `registry/upstream/<skill>/`. See [Forks](#forks).
  - **Third-party**: installed unmodified via `npx skills`. Never stored in this repo; only tracked in the registry.
- Keep installable skill content under `skills/<skill>/` only. Everything in those folders is copied verbatim into projects on install, so never put management metadata there.
- `registry/` holds management metadata, not installable skills:
  - `registry/projects.yaml` — the only hand-maintained input: project paths to scan.
  - `registry/upstream/<skill>/` — pristine upstream snapshots for forks.
  - `registry/third-party.md`, `registry/inventory.json` — generated ledgers; never hand-edit.

## Forks

A fork is a third-party skill you modified. Keep two copies:

- **Installable, modified copy**: `skills/<skill>/SKILL.md` — clean, no upstream files.
- **Pristine upstream snapshot**: `registry/upstream/<skill>/` — the unmodified upstream files plus `meta.yaml` (`source`, `ref`, `commit`, `upstream_path`, `local_path`, `fetched_at`, `notes`).
- Rename every `SKILL.md` inside a snapshot to `SKILL.md.orig`. `npx skills` discovers skills by the literal filename `SKILL.md` anywhere in the repo and has no ignore option (both verified), so a pristine `SKILL.md` would be wrongly registered as installable.
- On upstream updates: re-fetch upstream, diff against the snapshot, port wanted changes into the modified copy, then refresh the snapshot and `meta.yaml`.

See `registry/upstream/README.md` for the full layout.

## Registry

`registry/third-party.md` (human) and `registry/inventory.json` (machine) are GENERATED by `skills/manage-skills/scripts/sync-registry.mjs`. Never hand-edit them.

- The only hand-maintained input is `registry/projects.yaml` (project paths to scan).
- Data sources: the global lock `~/.agents/.skill-lock.json`, each scanned project's `skills-lock.json`, and the fork `meta.yaml` files under `registry/upstream/`.
- The ledger has three sections: global third-party, per-project third-party, and forks.
- Self-created skills (source `jfmoe/skills`, or local to this repo) are excluded from the third-party sections.
- Per-project reproducibility is owned by each project's `skills-lock.json`; the ledger is only a cross-project overview.
- Refresh after installing/removing/forking third-party skills, or after editing `projects.yaml`:

```bash
node skills/manage-skills/scripts/sync-registry.mjs
```

## Working Rules

- When creating, modifying, installing, updating, or recording skills, prefer the `manage-skills` skill if it exists. If it does not exist yet, follow this file and keep changes minimal.
- Do not manually edit installed/runtime skill directories such as `~/.agents/skills`, `~/.claude/skills`, `~/.cursor/skills`, or project `.agents/skills`.
- Use `npx skills ...` for installation and synchronization. Source edits belong in `~/Coder/skills`.
- Do not automatically commit or push unless the user explicitly asks.
- Use English in `README.md`, `AGENTS.md`, and skill files.

## Validation

After creating or modifying a skill, the default read-only validation is:

```bash
npx skills add ~/Coder/skills --list
```

For forks, confirm the snapshot under `registry/upstream/` is NOT listed as a skill (rename its `SKILL.md` to `SKILL.md.orig` if it is). After registry changes, regenerate the ledger with `sync-registry.mjs` and review the diff.

## Agent skills

### Issue tracker

Issues are tracked in this repo's GitHub Issues (via the `gh` CLI). External PRs are **not** a triage surface. See `docs/agents/issue-tracker.md`.

### Triage labels

Five canonical triage roles using their default label strings (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`). See `docs/agents/triage-labels.md`.

### Domain docs

Single-context layout — one `CONTEXT.md` + `docs/adr/` at the repo root. See `docs/agents/domain.md`.
