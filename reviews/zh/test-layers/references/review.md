# 审查套件

在审查、裁剪套件或给套件提速时加载。三条规则和分层树在 [SKILL.md](../SKILL.md) 中。

## 步骤

1. 按实际 *starts* 的东西给范围内每条测试打标（in-process、HTTP、子进程、数据库、浏览器）。完成：每条都有标签。
2. 走分层树。处置：`keep` / `demote` / `native+fixture` / `delete`。完成：每条都有处置，并写明层和规则。
3. 对照 [味道](#味道) 的每一行检查每条测试。完成：每个命中写明味道、测试和新处置。
4. 目标是提速时，给每条测试计时，并把时间拆成 setup、等待和被测规则三部分。完成：每条慢测试的时间都已归因，修复按省下的时间与改动成本排序。
5. `demote` 和 `delete` 先提案，同意后再改。完成：提案集合与处置一致。

**Delete with evidence.** 同一 oracle、同一输入类、没有多抓一种故障。相同的行覆盖仍可能藏着两个 oracle。

## 味道

味道是症状。确认它在消耗套件，再改处置。

| 味道 | 症状 | 何时保留 |
| --- | --- | --- |
| Fragile | 保持行为的重构仍迫使改测试。断言跟踪私有字段、内部名字或协作者调用顺序。 | 实现选择本身就是契约（从缓存提供、查询走索引）。为该保证命名。 |
| Change-detector | mock 和 `verify` / `assert_called_with`，不断言结果。生产和测试的 diff 形状相同。删掉它不会失去任何输入-输出关系。 | 真实边界上的交互（邮件已发、恰好扣费一次）本身就是行为。 |
| Tautological | 期望值按生产代码的算法算出；把生产公式用两遍是同一次计算，不是检查。 | 从不。把期望值换成字面量、规格里的值或算过的例子。 |
| Obscure | 一条测试里好几段行为、决定结果的数据在场外、巨大 fixture 只用一角、或隔着无关层驱动被测单元。 | 真实工作流本身就是单元。篇幅是情景。 |
| Assertion roulette | 许多裸断言；失败只报行号，不报行为。 | 对*同一个*结果的几项属性（解析记录上的 name、age、id）是一条规则。 |
| Erratic | 代码没变却时过时不过：顺序、时序、墙上时钟、未播种的随机、共享文件或行、用 sleep 当等待。 | 并发或随机就是被测对象，并且测试控制了它（种子、确定调度）。真实系统测试放在慢套件里。 |
| Slow | 测试的大部分时间花在 setup 或等待上，而不是规则上：每条测试前都跑一遍共享工作流、真的睡过一个期限、规则表里每一行起一个进程。 | 耗时*就是*边界（真实的 kill、真实的网络期限），且只有少数测试付出它。 |
| Duplication | 复制的 setup 或字面量，一次契约变更要改许多测试。 | 可读的重复让用例一目了然：输入和期望输出留在测试正文里。 |
| Wrong thing | getter、配置字面量、`class_exists`、框架胶水、已被真实调用方锻炼过的工具函数、为推覆盖率而加的测试、断言已退役行为被拒绝或不存在的测试。 | 可复用的解析器、日期规则或校验函数有可能写错的可枚举情形。监管限额 pin 的是它所保护的行为。 |
