# Test Layers

一条测试在一层（**layer**）上 *pin* 一条**规则**（**rule**），对照独立的 **oracle**。

1. **说出那个 red。** 写测试之前，写下哪条 bug 会让它 *red*，以及期望值从哪来：字面量、规格、算过的例子。没有这样的 bug，就没有测试：框架胶水、配置字面量和 getter 由它们驱动的行为覆盖。从未执行的代码是通向规则的线索，覆盖率不是写测试的理由。
2. **最便宜的一层。** 把规则 pin 在能观察到该失败的最便宜一层，并且只 pin 一次。
3. **断言调用者看到的东西。** 公共接口上的返回值、错误和可见副作用，这样保持行为的重构不需要动测试。

审查或裁剪套件、给套件提速 → 按 [references/review.md](references/review.md) 做。

## Layers

```text
这条测试 pin 哪条规则？
  更便宜的一层已经 pin 了同一输入类、失败模式和 oracle？
    是 → 停
    否 → 真正的失败出现在哪？
          同进程逻辑                               → in-process
          进程、信号、线、崩溃、冻输入             → boundary
          第三方引擎原生结果                       → native
```

**in-process.** 单元的公共 API；fake 下一跳 I/O。计算、排队、映射、校验、状态机、持久化规则（真实的临时存储算作 in-process）。

**boundary.** 把那条进程、线或 OS 事实真正跑起来，并写明 in-process 观察不到的那个事实。只是*经过*边界的规则不是边界规则：在 in-process 中 pin 住规则，然后每个边界保留几条代表路径，而不是每条规则一条。HTTP 鉴权、杀进程/崩溃隔离、需要 JS 或可视状态的浏览器旅程。

**native.** 对引擎做一次真正的 execute。字段映射用夹具。查询语义、渲染等引擎结果留在 native；fake 永远不能代替它们。

从 **in-process** 起。规则本身就是边界或原生引擎结果时再升级。

接缝（seam）和层是两个独立的选择：接缝是测试调用哪个接口，层是它启动多少真实设施。模块的最高接缝，在 in-process 中驱动并 fake 下一跳 I/O，同时满足两者。

## 写的时候

**一条测试一条规则**，以保证命名。共享 setup 和断言 → 一张表。不同失败模式 → 分开。生产代码并不分支的输入留在表里。

**调用顺序仅作为契约。** 只有当内部调用顺序本身就是保证时（只扣一次费、从缓存提供）才断言它；为该保证命名。

**Minimal setup.** setup 只构造规则会读取的东西。直接准备状态，而不是跑一遍无关的工作流（安装、完整服务启动、登录、一条 UI 路径）去到达它；那条工作流有自己的测试。

**Isolated.** 任意顺序，同一结果。在边界注入时钟、种子和 I/O；期限靠注入的时钟推进。断言某事*没有*发生之前，先等待处理完成的信号。Flake 隔离或修好。

**退役的行为连同它的测试一起离开。** 删除本身就是证据，因此不写断言旧命令、旧字段或旧路由现在被拒绝或不存在的测试。

**看耗时。** 运行测试；每一秒慢都属于规则本身或它的边界事实。

## Examples

- 队列 / 并发上限 → in-process（打桩计算槽）。
- 超时能杀掉计算；崩溃不留半截行 → boundary（真进程）。
- 超时*分类*（迟到的结果变为“未知”）→ in-process（fake 时钟）。
- 重启后不重复执行 → in-process（重新打开同一存储）。
- 领域对象 → JSON → in-process（夹具）。
- HTTP 鉴权 → boundary（一条真实请求）。handler 里的计算 → in-process。
- 需要 JS 的浏览器旅程 → boundary。每种失败原因的错误文案 → in-process 组件测试。
