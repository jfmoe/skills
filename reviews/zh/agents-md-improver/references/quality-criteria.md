# AGENTS.md 质量标准

产出打分的 AGENTS.md 审计时使用本评分细则。可根据仓库调整说明，但评分口径应保持一致。

## 评分细则

总分：100 分。

| 标准 | 分值 | 评估内容 |
| --- | ---: | --- |
| 命令/工作流 | 15 | 构建、测试、lint、安装、运行、部署、验证以及常见维护命令已记录且保持最新。 |
| 项目结构 | 15 | 重要目录、入口点、包边界和所有权范围清晰。 |
| agent 专属规则 | 20 | 编辑约束、批准、语言、工具偏好、安全规则以及仓库特定行为都有明确规定。 |
| 非显而易见的模式 | 15 | 捕获了生成文件、怪癖、陷阱、约定、本地工作流和集成细节。 |
| 简洁性 | 10 | 内容信息密集、无冗余，避免泛泛的建议。 |
| 时效性 | 15 | 指令与当前的文件、脚本、依赖和工作流现状一致。 |
| 可执行性 | 10 | 规则足够具体，agent 无需猜测即可遵循。 |

## 等级区间

- **A（90-100）**：未来的 agent 几乎不需要重新探索即可高效工作。指令简洁、最新且有明确作用范围。
- **B（70-89）**：有用且基本最新，仅有有限的缺口或轻微的冗长。
- **C（50-69）**：存在基本指引，但缺少重要的工作流、约束或结构说明。
- **D（30-49）**：稀疏、含糊、重复或过时到足以导致反复出错。
- **F（0-29）**：缺失、误导或有害的指令。

## 各项标准详解

### 命令/工作流

满分要求命令可直接复制粘贴或有清晰描述。当命令必须从特定路径运行时，需注明工作目录要求。

需要标记的情况：

- package/配置文件中列出的脚本未被记录
- 已记录的命令在当前仓库中不存在
- 编辑之后缺少验证命令
- 非标准的设置或依赖安装步骤缺失

### 项目结构

满分要求提供足够的结构信息，使 agent 能在编辑前选对文件。

需要标记的情况：

- monorepo 的包边界未被描述
- 应用/库/配置/生成目录无法区分
- 缺少重要的入口点
- 嵌套的 AGENTS.md 文件重复父级上下文却遗漏本地作用域

### agent 专属规则

满分要求指令能影响 agent 的行为，而不仅仅是给人看的文档。

需要标记的情况：

- 缺少关于生成文件、vendor 代码、锁文件或运行时安装目录的规则
- 缺少针对破坏性操作、网络、部署或全局编辑的批准关卡
- 语言或格式规则相互冲突
- 项目特定的工具偏好未被记录

### 非显而易见的模式

满分要求提供无法从文件名或标准工具链中看出的持久上下文。

需要标记的情况：

- 隐藏的环境假设
- agent 需要知道的本地服务或端口
- 特殊的测试数据、fixture 或 mock
- 已知不稳定的测试或必需的执行顺序
- 必须通过特定命令刷新的生成输出

### 简洁性

满分要求每一行都有高信息量。

需要标记的情况：

- 泛泛的最佳实践
- 用一条命令或一条规则就足够的长篇文字
- 嵌套文件之间重复的章节
- 无法指导未来工作的会话历史

### 时效性

满分要求根据当前仓库证据核对指令。

需要标记的情况：

- 执行失败或引用了已移除工具的命令
- 已不存在的文件路径
- 与当前布局矛盾的架构说明
- 未经适配就从其他项目复制过来的规则

### 可执行性

满分要求指令无歧义。

需要标记的情况：

- 像“遵循最佳实践”这样没有项目特定含义的含糊表述
- 规则缺少位置、命令或条件
- 只描述目标而不描述可操作行为的指令

## 推荐的证据检查

打分之前进行轻量级的仓库检查：

```bash
rg --files -g 'package.json' -g 'pnpm-lock.yaml' -g 'yarn.lock' -g 'package-lock.json' -g 'pyproject.toml' -g 'Cargo.toml' -g 'go.mod' -g 'Makefile' -g 'justfile'
```

```bash
rg -n 'scripts|test|lint|build|dev|format|typecheck|deploy' package.json pyproject.toml Makefile justfile 2>/dev/null
```

不要为一次简单的 AGENTS.md 更新在探索上过度投入。目标是改进 agent 上下文，而不是对整个代码库做详尽审计——除非用户要求那样的深度。
