# AGENTS.md 改进器

审计、评估并改进 AGENTS.md 指令文件，使未来的 agent 会话能够获得简洁、最新、可执行的项目上下文。

本 skill 仅限手动调用。仅当用户明确要求使用 `agents-md-improver` 或直接要求运行本 skill 时才使用。

本 skill 只有在先提交质量报告或拟议新增内容并获得用户明确批准后，才能写入 AGENTS.md 文件。

## 模式

- **审计模式**：检查 AGENTS.md 文件、评估质量得分、提出针对性更新建议，然后应用已批准的更改。
- **会话学习模式**：回顾当前会话中可持久化的经验，提出简短的 AGENTS.md 新增内容，然后应用已批准的更改。

## 阶段 1：发现

查找相关的 agent 指令文件。

针对当前仓库：

```bash
find . \( -name "AGENTS.md" -o -name ".agents.md" \) -not -path "*/node_modules/*" -not -path "*/.git/*" 2>/dev/null | head -50
```

对于明确要求的全局或外部位置，只检查用户点名的路径。常见的全局候选包括：

- `~/.agents/AGENTS.md`
- `~/.codex/AGENTS.md`
- 当用户有意桥接 Claude 风格的指令时，检查 `~/.claude/CLAUDE.md`
- 其他用户指定的 agent 指令文件

不要静默编辑全局文件。全局文件需要用户明确的意图和批准。

## 文件类型与放置位置

| 类型            | 位置                                                                      | 用途                                                                |
| --------------- | ------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 项目根目录      | `./AGENTS.md`                                                             | 共享的仓库指令和项目级规则                  |
| 嵌套作用域      | `./packages/*/AGENTS.md`、`./apps/*/AGENTS.md`，或任何嵌套的 `AGENTS.md` | 覆盖或细化父级上下文的目录特定指令 |
| 本地/私有       | `./.agents.md` 或用户指定的本地文件                             | 个人或仅本地使用的指令，通常被 gitignore 忽略                |
| 全局默认值      | 用户指定的全局路径                                               | 跨项目的偏好设置和持久的 agent 默认配置                   |

当存在多个文件时，将每条新增内容放置在仍然有效的最窄作用域中。

## 阶段 2：质量评估

对每个文件，评估它是否能帮助 agent 以最少的额外探索正确行动。进行打分审计时，阅读 [references/quality-criteria.md](references/quality-criteria.md)。

快速检查清单：

| 标准                  | 权重   | 检查项                                                                                     |
| ---------------------- | ------ | ----------------------------------------------------------------------------------------- |
| 命令与工作流           | 高     | 相关时是否记录了构建、测试、lint、部署、安装和验证命令？ |
| 项目结构               | 高     | agent 能否理解重要目录、入口点和所有权边界？    |
| agent 专属规则         | 高     | 关于编辑、批准、工具、语言、风格和安全的约束是否清晰？         |
| 非显而易见的模式       | 中     | 是否捕获了陷阱、约定、生成文件和集成怪癖？               |
| 简洁性                 | 中     | 文件是否信息密集且有用，没有泛泛的建议或显而易见的复述？              |
| 时效性                 | 高     | 是否与当前仓库和工具链一致？                                         |
| 可执行性               | 高     | 指令是否具体、可执行且有明确的作用范围？                                        |

质量等级：

- **A（90-100）**：全面、最新、简洁且可执行
- **B（70-89）**：覆盖良好，仅有少量缺口
- **C（50-69）**：有基本指引但缺少重要细节
- **D（30-49）**：稀疏、含糊或明显过时
- **F（0-29）**：缺失、误导或严重过时

## 阶段 3：质量报告

在编辑文件之前始终先输出报告。

使用以下格式：

```markdown

- Files found: X
- Average score: X/100
- Files needing update: X

### File-by-File Assessment

#### 1. ./AGENTS.md (Project Root)

**Score: XX/100 (Grade: X)**

## 阶段 4：针对性更新

报告之后，询问用户是否要进行更改。编辑之前，以 diff 或引用块的形式展示拟议的更改。

更新准则：

1. 只添加持久的、项目特定的信息。
2. 尽可能每个概念只占一行。
3. 指令的作用范围应与文件所在位置保持一致。
4. 保留现有的结构和语气。
5. 避免在嵌套文件中重复父级指令，除非重复的规则能防止真实的错误。

避免添加：

- agent 本来就知道的通用最佳实践
- 仅从文件名就能看出的显而易见的事实
- 不太可能重现的一次性会话细节
- 用一条命令或一条简短规则就足够的大段解释
- 与更高优先级的用户或系统指令冲突的工具或工作流规则

Diff 格式：

````markdown
### Update: ./AGENTS.md

**Why:** Build validation was missing, so future agents would not know the expected check.

````diff
+ ## Validation
+
+ ```bash
+ npm test
+ ```
````
````

## 阶段 5：应用已批准的更新

只应用用户批准的更改。保留现有内容，避免无关的重写。

编辑之后：

1. 重新阅读更改过的部分，验证放置位置和格式。
2. 在可用时运行轻量级验证，例如 Markdown 格式检查或项目文档中记录的验证命令。
3. 总结更改过的文件以及任何无法运行的验证。

## 会话学习模式

当用户要求根据当前会话修订 AGENTS.md 时使用此模式。

### 步骤 1：反思

识别对未来 agent 有帮助的持久上下文：

- 被发现或验证过的命令
- 遵循过的代码风格或仓库约定
- 行之有效的测试或验证方法
- 环境、工具、权限或配置方面的怪癖
- 警告、生成文件或 agent 应避免编辑的区域
- 批准关卡或人工工作流偏好

### 步骤 2：查找目标文件

首先查找仓库文件：

```bash
find . \( -name "AGENTS.md" -o -name ".agents.md" \) -not -path "*/node_modules/*" -not -path "*/.git/*" 2>/dev/null | head -20
```

仅当用户明确要求更新全局指令时才使用全局文件。

### 步骤 3：起草新增内容

保持新增内容简洁。首选格式：

```text
<command, rule, or pattern> - <brief reason or usage>
```

选择能从该经验中受益的最窄范围的文件。

### 步骤 4：展示拟议更改

对每条新增内容，展示：

- 目标文件
- 一行理由
- Diff 或引用块

编辑之前请求批准。

### 步骤 5：经批准后应用

只编辑用户批准的文件。

## 模板

创建缺失的 AGENTS.md 或文件需要实质性重构时，阅读 [references/templates.md](references/templates.md)。

## 需要标记的常见问题

1. 已不存在或与 package 脚本不匹配的过时命令
2. 缺少验证或测试指令
3. 缺少仓库特定的编辑约束
4. monorepo 中所有权边界不清晰
5. 嵌套指令重复父级文件内容却没有增加本地价值
6. 父级文件与嵌套文件之间的指令冲突
7. 占用提示词空间却不指导行动的长篇通用章节
8. 未标记的生成文件或 vendor 文件，agent 可能会意外编辑
9. 全局偏好被放进项目文件，或项目特定规则被放进全局文件

## 优秀 AGENTS.md 的特质

- 简洁易读
- 与仓库实际的命令和结构保持同步
- 明确说明 agent 应该做什么、避免什么、询问什么、验证什么
- 作用范围限定在其所在目录
- 聚焦于反复出现的上下文，而非一次性的历史
- 以指令的口吻书写，而非评论
