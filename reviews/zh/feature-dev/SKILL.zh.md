# 功能开发

你正在帮助一位开发者实现一个新功能。遵循系统化的方法：深入理解代码库，识别并询问所有未明确的细节，设计优雅的架构，然后实现。

## Codex 适配

- 本 skill 仅手动触发。仅在用户明确要求使用 `feature-dev` 时使用。
- 全程使用 Codex 的 todos/plan 更新来跟踪所有进度。
- 启动 subagent 时，按名称显式生成 Codex 自定义 agent：`code-explorer`、`code-architect` 和 `code-reviewer`。
- 将 `AGENTS.md` 视为项目特定 agent 指令的来源。

## 核心原则

- **提出澄清性问题**：识别所有歧义、边界情况和未明确的行为。提出具体、明确的问题，而不是做假设。在继续实现之前等待用户的回答。尽早提问（在理解代码库之后、设计架构之前）。
- **先理解再行动**：首先阅读并理解现有的代码模式
- **阅读 agent 识别出的文件**：启动 agent 时，要求它们返回最需要阅读的文件清单。agent 完成后，阅读这些文件以建立详细的上下文，然后再继续。
- **简单而优雅**：优先考虑可读、可维护、架构合理的代码
- **使用 Codex 的 todos/plan 更新**：全程跟踪所有进度

---

## 阶段 1：需求发现

**目标**：理解需要构建什么

初始请求：用户的功能描述

**行动**：
1. 创建包含所有阶段的 todo 列表
2. 如果功能不清晰，向用户询问：
   - 他们要解决什么问题？
   - 该功能应该做什么？
   - 有任何约束或要求吗？
3. 总结你的理解并与用户确认

---

## 阶段 2：代码库探索

**目标**：在宏观和微观两个层面理解相关的现有代码和模式

**行动**：
1. 并行启动 2-3 个 code-explorer agent。每个 agent 应当：
   - 全面地追踪代码，重点全面理解抽象、架构和控制流
   - 针对代码库的不同方面（例如：相似功能、高层理解、架构理解、用户体验等）
   - 包含一份 5-10 个关键文件的阅读清单

   **示例 agent 提示词**：
   - "Find features similar to [feature] and trace through their implementation comprehensively"
   - "Map the architecture and abstractions for [feature area], tracing through the code comprehensively"
   - "Analyze the current implementation of [existing feature/area], tracing through the code comprehensively"
   - "Identify UI patterns, testing approaches, or extension points relevant to [feature]"

2. agent 返回后，请阅读 agent 识别出的所有文件，以建立深入理解
3. 呈现对发现和所发现模式的全面总结

---

## 阶段 3：澄清性问题

**目标**：在设计之前填补空白并解决所有歧义

**关键**：这是最重要的阶段之一。不要跳过。

**行动**：
1. 回顾代码库的发现和原始功能请求
2. 识别未明确的方面：边界情况、错误处理、集成点、范围边界、设计偏好、向后兼容性、性能需求
3. **以清晰、有条理的列表形式向用户呈现所有问题**
4. **等待回答后再进行架构设计**

如果用户说"你觉得怎么好就怎么来"，给出你的建议并征得明确确认。

---

## 阶段 4：架构设计

**目标**：设计多种具有不同取舍的实现方案

**行动**：
1. 并行启动 2-3 个 code-architect agent，各自侧重不同方向：最小改动（改动最小、复用最大）、整洁架构（可维护性、优雅的抽象）、或务实平衡（速度 + 质量）
2. 审视所有方案，并形成你对哪个方案最适合这个具体任务的看法（考虑因素：小修复 vs 大功能、紧急程度、复杂度、团队背景）
3. 向用户呈现：每种方案的简要总结、取舍对比、**你附理由的推荐**、具体的实现差异
4. **询问用户偏好哪种方案**

---

## 阶段 5：实现

**目标**：构建该功能

**未经用户批准不要开始**

**行动**：
1. 等待用户的明确批准
2. 阅读之前阶段识别出的所有相关文件
3. 按照所选架构进行实现
4. 严格遵循代码库约定
5. 编写干净、文档完善的代码
6. 随进度更新 todos

---

## 阶段 6：质量审查

**目标**：确保代码简单、DRY、优雅、易读且功能正确

**行动**：
1. 并行启动 3 个 code-reviewer agent，各自侧重不同方向：简洁/DRY/优雅、缺陷/功能正确性、项目约定/抽象
2. 汇总发现，识别你建议修复的最高严重级别问题
3. **向用户呈现发现，并询问他们想如何处理**（立即修复、稍后修复，或按现状继续）
4. 根据用户的决定处理问题

---

## 阶段 7：总结

**目标**：记录已完成的工作

**行动**：
1. 将所有 todos 标记为完成
2. 总结：
   - 构建了什么
   - 做出的关键决策
   - 修改的文件
   - 建议的后续步骤
