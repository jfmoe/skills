# Fowler 式重构

## 是什么

重构，按 Martin Fowler 的精确定义，是**在不改变外部可观察行为的前提下重组既有代码**。同样的输入产生同样的输出；调用者依赖的副作用得到保持。改变的是内部结构：名字变得更清晰，职责搬到更合适的归属处，长函数拆成有名字的阶段，重复的知识收敛到一处。

这比日常说的"我重构了代码"要窄——那句常常意味着"我重写了它，顺手改了一些行为"。当可观察行为发生变化时，那就不是重构；那是功能变更、bug 修复或性能优化。把这些活动分开，就是这门纪律的全部。

Fowler 的《重构》把一个**代码坏味道**目录（提示结构问题的症状）与一个**具名重构**目录（对付这些问题的、保持行为的小型变换）配对。坏味道告诉你*往哪里看*；重构告诉你*怎么以受控的步骤修复*。坏味道一侧见 [code-smells.md](./code-smells.md)，变换一侧见各技术文档，如 [extract-function.md](./extract-function.md)。

## 纪律：小步前进，一次只做一件事

定义性的实践是每一步的大小。一次重构是一连串微小的变换，每一步都小到显而易见地正确，并且每步之后测试重新变绿。你重命名一个变量，跑测试。你提炼一个函数，跑测试。你把它搬到另一个类，跑测试。如果某一步弄坏了什么，你确切知道是哪个改动造成的，因为你只做了一个。

这与"让我重构整个模块然后看看还能不能跑"恰好相反。大规模未经验证的重组正是重构出事的地方：当测试在最后失败时，你无法分辨自己引入了一个 bug 还是五个，而安全的做法变成了把工作整个扔掉。小步前进让你始终处于可工作的状态，于是你可以在任何一点停下，手里仍然是可发布的代码。

一次只做一件事还意味着**永远不在同一步里混合重构与功能变更**。Fowler 把它描述为戴"两顶帽子"：加功能时，不同时清理结构；重构时，不增加能力。你有意地、频繁地换帽子，但你始终知道自己戴的是哪一顶。混合两者之所以危险，是因为合并变更之后的绿色测试什么也说明不了；你无法把结果归因于其中任何一项活动。实践中这意味着重构与行为变更应当分属不同的提交，或者至少被分别标明。安全机制见 [safe-refactoring.md](./safe-refactoring.md)。

## 什么时候重构

重构不是一个排到以后的独立阶段。它织在日常工作里，有三个自然时机：

- **准备性重构。** 加功能之前，先重塑代码让功能干净地嵌入。"让变更变得容易，然后做那个容易的变更。"如果一个函数需要一个新参数，而它的三个调用方各自都需要别扭的处理，先重构让接缝存在，再通过它加功能。这是价值最高的时机，因为重组立刻就有回报。
- **理解性重构。** 当你终于看懂一段令人困惑的代码时，把这份理解折回代码里：重命名误导性的变量，提炼未命名的概念，补上缺失的结构。你反正要花力气去理解它；把结果留存下来意味着下一位读者不必再花。
- **清理性重构。** 当你触碰到比它应有的样子更缠结的代码时，让它比你找到时好一点。童子军规则。这以判断力为界：清理挡你路的东西，而不是整个模块。

## 什么时候不要重构

- **没有测试，也没有任何其他安全网。** 重构依赖一种能快速确认行为得到保持的方式。没有测试、特征化测试（characterization test）、类型检查或某种可重复的验证手段，你就不是在重构，而是在编辑并祈祷。要么先补安全网（见 [safe-refactoring.md](./safe-refactoring.md)），要么不要碰结构。
- **没有安全网的死线压力。** 在真实的死线之下，大规模投机性重组是坏赌注。小而安全的步骤没问题，甚至有帮助；可能做不完的高风险重塑则不行。
- **你即将整批删除或替换的代码。** 打磨下周就要扔掉的结构是浪费力气。YAGNI 同样适用于清理。
- **当你会改变自己无法验证的行为时。** 如果代码触及公开 API、序列化 schema 或 CLI 参数，"只是整理一下"可能会悄悄弄坏使用者。先定义可观察契约，或者把这项工作当作行为变更而非重构来对待。

## 坏味道指路，重构动刀

两个目录之间的关系是诊断性的。坏味道——长函数、重复代码、有依恋情结的方法——是*症状*，不是判决。它让你凑近看，而不是机械行动。一旦你证实了底层的结构问题，就挑一个能对付它的具名重构，以小步应用。坏味道是问题本身；重构是可能的答案之一。这能防止你"修复"其实没坏的东西，也能防止你在一次重命名就能解决时动用重型变换。

在 agent 辅助开发中，"先闻味道、再做重构"的循环更重要而非更不重要：代码积累得更快，所以结构问题出现得更快，而重写而非变换的诱惑也更强。保持行为的小步前进这门纪律，正是让快速移动的代码不至于漂移到无人能验证的状态的东西。
