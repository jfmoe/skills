# 内联函数

## 是什么

内联函数是 [extract-function.md](./extract-function.md) 的逆操作：它用函数体替换调用，并删除该函数。提炼函数把一个概念抽出来变成一个名字；内联函数则在名字不再挣得自己的位置时把函数折回去——当函数体表达的和调用一样多，或表达得更清晰时。

```python
# before
def get_rating(driver):
    return 2 if more_than_five_late_deliveries(driver) else 1

def more_than_five_late_deliveries(driver):
    return driver.late_deliveries > 5

# after
def get_rating(driver):
    return 2 if driver.late_deliveries > 5 else 1
```

## 什么时候内联

- **误导性的名字。** 当函数名对函数体的描述还不如函数体对自己的描述时，这层间接是在主动误导。内联能移除一个错误的路标。
- **琐碎的委托。** 一个除了转发给另一个函数之外什么都不做的函数；即 [thin-wrapper-function.md](./thin-wrapper-function.md) 描述的薄包装。当它背后没有边界、没有测试接缝、没有不稳定的依赖时，内联它。
- **函数体比调用更清晰。** 有时一个单行函数遮蔽了一个每个读者都已理解的简单表达式。调用迫使读者跳过去确认一件显而易见的事；内联让读者的视线留在原地。
- **逆转过早的提炼。** 当较早的一次重构（常常是 agent 生成的）沿错误的接缝把代码切成许多小辅助函数时，把其中几个内联回来能让你看清真实形状，再沿更好的边界重新提炼。Fowler 的建议：当间接没有帮助时，先内联，再重新提炼。

## 内联前的安全检查

- **多态与覆写。** 不要内联在子类中被覆写的方法，或分派有意义的方法：内联会塌缩掉类型系统本来在挑选的行为。
- **递归与多个调用点。** 递归函数不能被天真地内联。调用方很多时，处处内联可能是个大改动；动手之前考虑这个函数是否真的在出力，并逐个调用点地内联。
- **副作用与求值顺序。** 确保把函数体折进来不会改变表达式的求值时机，尤其当参数有副作用或函数体读取可变的共享状态时。
- **行为保持。** 与所有重构一样，每次内联后跑测试。见 [safe-refactoring.md](./safe-refactoring.md)。IDE 提供"内联方法"，能处理机械替换并更新所有调用点。

## 什么时候不要内联

当函数在不稳定实现之上提供稳定接口、创造测试接缝、命名了一个有助于搜索和理解的真正领域概念、或隐藏了真实复杂度时，保留它。仅有短永远不构成内联的理由；一个位于清晰边界上的、命名良好的小函数是好设计，不是坏味道。问题在于名字和边界是否增添了意义，而不是它们背后有多少行。
