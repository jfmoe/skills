# 代码坏味道

## 什么是坏味道

代码坏味道是一个**提示存在更深层结构问题的表面症状**，但它本身不是问题，也不是判决。Kent Beck 刻意用"气味"来类比创造了这个词：它让你停下来凑近看看，而不是证明哪里确实有问题。长函数可能是问题，也可能是一个读起来顺畅的清晰线性序列。重复代码可能是把一条规则编码在了三个地方，也可能只是三个今天恰好相似的片段。

这个区分——是症状，不是诊断——是关于坏味道最重要的一点。把坏味道当成自动成立的缺陷，会导致让代码变糟的机械式"修复"：抽取了本不需要抽取的函数、去掉了其实并不算重复的重重、为永远不会到来的变化引入了抽象。坏味道是一封调查的邀请函，而调查完全可以合理地得出结论："这没问题。"

## 主要类别

Fowler 和 Beck 把坏味道分成了若干家族。知道家族能帮助你找到正确的修复方式。

- **膨胀者（Bloaters）**：已经膨胀到难以舒适处理的代码。长函数、过大的类、过长参数列表、数据泥团、基本类型偏执。这些是逐渐积累起来的；每次新增都显得合理，直到整体变得笨重。见 [long-function.md](./long-function.md) 和 [primitive-obsession.md](./primitive-obsession.md)。
- **面向对象误用者（Object-orientation abusers）**：对 OO 机制的不完整或不正确使用。本该用多态的 Switch 语句、被拒绝的遗赠、临时字段、接口不同的相似类。
- **变更阻碍者（Change preventers）**：一次变更会迫使许多其他变更的结构。发散式变化（一个模块因许多原因被修改）和霰弹式手术（一次变更散落在许多模块里）是两个经典的、彼此相反的形态。见 [divergent-change.md](./divergent-change.md) 和 [shotgun-surgery.md](./shotgun-surgery.md)。
- **冗余品（Dispensables）**：缺了它们代码会更干净的东西。重复代码、死代码、投机性通用化、多余的元素（一个挣不出自己存在价值的类或函数：与薄包装函数密切相关，见 [thin-wrapper-function.md](./thin-wrapper-function.md)）、用来解释烂代码的注释。见 [duplicated-code.md](./duplicated-code.md)。
- **耦合者（Couplers）**：模块间过度耦合的坏味道。依恋情结、狎昵关系、消息链、中间人。见 [feature-envy.md](./feature-envy.md)。

这些类别彼此重叠，一段代码可以同时表现出好几种。分类法的意义在于回忆：当有什么感觉不对劲时，这些家族能提示你说出自己看到的是什么。

## 如何分诊：现在值得修吗？

发现坏味道是容易的部分。判断是否动手，答案常常是"现在不修"。做一次快速分诊：

1. **它已被证实，还是只是个形状？** 看穿表面。重复代码真的是一条规则，还是两条看着像的规则？长函数是在混合抽象层次，还是一个清晰的序列？如果你说不出底层结构问题是什么，到此为止。
2. **它挡你的路了吗？** 你正在改动、或即将改动的代码里的坏味道值得修：准备性重构和理解性重构立刻就有回报。没人触碰的稳定代码里的坏味道通常最好放着不管；改动能工作的代码的风险大于整洁收益。
3. **留着它的代价是什么？** 高风险的知识重复（安全、金钱、协议契约、schema）无论出现频率如何都值得见到就修，因为发散的代价高昂。安静角落里一个稍微过长的函数则不值得。
4. **有安全网吗？** 如果你无法验证行为得到保持，就先不要重构结构。见 [safe-refactoring.md](./safe-refactoring.md)。

分诊的目标是把重构精力花在能减少真实未来成本的地方，而不是把每个坏味道计数清零。

## agent 辅助开发中的坏味道

agentic 编码同时提高了代码生产的速度和坏味道出现的速度。其特征性问题不是"代码看起来不像人写的"，而是结构性的：重复的适配器、薄包装辅助方法、过宽的 Protocol、投机性的注册表、深层 mock、同一条领域规则被分别写在 schema、服务和测试夹具里。因为数量更大，坏味道检测必须比传统手写代码更主动、更刻意，但上面的分诊纪律也更重要了——因为诱惑是把 agent 产出的一切都机械地"清理"一遍。

## 与专门文档的关系

本文档是地图。本目录中的每个专门叶子文档深入讲一种坏味道或一种变换：它到底是什么、区分真问题和假警报的信号、什么时候这个坏味道其实可以接受、以及哪个具名重构可以对付它。当分诊说某个坏味道值得调查时，路由到对应的具体文档。变换本身——提炼函数、内联函数、搬移函数——在 [extract-function.md](./extract-function.md)、[inline-function.md](./inline-function.md) 和 [move-function.md](./move-function.md) 里，而安全地应用它们的整体纪律在 [fowler-refactoring.md](./fowler-refactoring.md) 里。
