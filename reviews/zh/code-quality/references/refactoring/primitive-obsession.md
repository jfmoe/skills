# 基本类型偏执

## 是什么

基本类型偏执是这样一种习惯：在本该用专门类型换取安全和清晰的地方，用裸基本类型——字符串、整数、浮点数、裸元组和无类型的字典——来表示领域概念。用户 ID "只是个字符串"，货币金额"只是个浮点数"，订单状态"只是这几个字符串值之一"，坐标"只是两个数字的元组"，解析出的记录"只是个 `dict[str, Any]`"。每个决定单独看都方便，合在一起却把领域从代码里抹掉了。

代价是基本类型不携带意义、不执行任何规则。一个接受 `(str, str, str)` 的函数不会帮助调用者记住哪个字符串是邮箱、哪个是名字、哪个是城市，也没有什么能阻止他们把三者按错误顺序传入。用 `float` 表示金额，等于邀请另一个表示数量的 `float` 以错误单位与它相乘。用字符串表示的状态可以装下 `"shippped"`，直到上线都没人发现。本可以抓住这些的类型系统，什么信息都没被告知。

## 信号

- **校验散落在各调用点。** 同样的 `if not re.match(EMAIL_RE, value)` 出现在每个收到邮箱字符串的地方，因为字符串本身不保证任何东西。值对象在构造时校验一次。
- **固定成群出现的基本类型。** 经纬度总是一起传，`currency` 和 `amount_cents` 总是并肩出现：这些数据泥团想成为一个类型。
- **字符串化的状态与类别。** 一个实际上是枚举的字段被存成自由字符串，并在代码各处与字符串字面量比较。
- **拿 `dict[str, Any]` 当伪记录。** 形状已知且固定的数据以字典形式传来传去，每次访问都是一次类型检查器无法验证、打错字要到运行时才暴露的字符串化查找。
- **依附于类型却无处安放的行为。** 操作基本类型的函数（格式化这个电话号码、规范化这个代码）堆成自由函数，因为没有类型可以挂上去。

## 什么时候引入领域类型

当一个概念有自己的校验规则、不变量或相关行为时——金额、邮箱、日期区间、坐标——引入**值对象**（在 Python 里是 `frozen` dataclass、`NamedTuple` 或小类）。当一个值属于一个固定、已知的集合时，引入**枚举**（`Enum`、`StrEnum`）；这把笔误变成错误，并给你 `match` 中的穷尽性检查。当一个 `dict[str, Any]` 形状已知时，引入**类型化记录**（`dataclass`、`TypedDict`、Pydantic 模型），让字段访问被检查、结构被类型所记录。

回报是集中：校验在构造该类型的边界处发生一次，不变量在该类型被使用的每一处都成立，行为有了显而易见的家。非法状态变得无法表示，而不仅仅是概率低。

## 什么时候基本类型没问题

领域类型不是免费的——它们增加一个定义、一步构造和一层间接——过度使用本身就是坏味道。以下情况基本类型是正确选择：

- **内部管道。** 循环下标、临时计数、局部累加器；这些确实只是数字，包装它们只会增加噪音而没有安全。
- **真正通用的代码。** 序列化器、缓存、通用容器、或应当对*任何*值都工作的日志辅助方法，没有理由了解你的领域类型；基本类型和泛型在那里是正确的。
- **性能关键路径。** 把大型数值数组的每个元素包成值对象可能是真实代价。在热点数值代码里，基本类型数组（或 NumPy dtype）是合适的，领域含义在别处记录。
- **概念没有规则也没有行为。** 如果一个字符串只是一个从不被校验、从不与固定集合比较、也不被操作的不透明标签，一个 `NewType` 别名可能就是它需要的全部清晰度——或者什么都不需要。

判断标准是这个概念是否*挣得*一个类型：包装它能防止某一类错误、集中某条规则、或给行为一个家吗？如果能，引入类型。如果只增加仪式，留下基本类型。
