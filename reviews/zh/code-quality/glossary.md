# 术语表

这些术语在本 Skill 中带有特定含义。当判断需要示例或更完整的标准时，使用 [SKILL.md](./SKILL.md) 中的路由表。

## 审查语言

**事实**

在代码、配置、测试或运行时行为中可直接观察到的东西。

**推断**

从事实得出的、仍可能存在其他解释的结论。

**判断**

针对某个明确的工程关切或权衡，对证据作出的评估。

**建议**

针对有证据支持的发现或清晰界定的问题所提出的最小充分行动。

**发现**

一个有证据支持的关切，陈述证据、影响和建议。单纯的风格偏好不是发现。

**误报**

在考虑了周围约束或意图之后不再成立的、看似合理的关切。

## 设计边界

**变更边界**

应当吸收某类预期变更、而不迫使其他地方做不相关修改的模块或组件。

**语义边界**

命名并强制一个真实概念的函数、类型或模块边界，而不是仅仅转发工作。

**变化点**

一个已知或可合理预期会变化、从而可能值得引入间接层的行为维度。

**深模块**

用小接口隐藏大量实现细节或策略的模块。

**浅模块**

接口暴露的复杂性几乎与其实现一样多的模块。

## 重构与测试

**知识重复**

同一条规则或决策被编码在不止一个地方。仅仅文本相似不算重复。

**错误的抽象**

把变化原因或变化方向不同的代码合并在一起的共享抽象。

**薄包装**

不增加任何策略、语义命名、隔离或稳定接口的转发函数或类型。

**变更侦测器测试**

因为断言内部调用或结构，而在保持行为的重构时失败的测试。

**测试接缝**

可以控制或替换依赖、从而确定性地测试行为的边界。
